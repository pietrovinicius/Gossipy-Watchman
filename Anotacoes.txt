----------------------------------------------------------------
SOBRE O PROJETO
----------------------------------------------------------------
Sistema web de análise de vídeo para identificação, catalogação e
registro temporal de pessoas via reconhecimento facial. Backend em
FastAPI + SQLite com pipeline assíncrono usando OpenCV e face_recognition.
Objetivo: portfólio técnico de nível sênior demonstrando arquitetura
assíncrona, visão computacional e separação limpa de camadas.

CONFIGURAÇÃO INICIAL (PRIMEIRA VEZ)
================================================================

Passo 1 — Clonar o repositório
  git clone <URL_DO_REPOSITORIO>
  cd gossipy-watchman


Passo 2 — Criar e ativar ambiente virtual

  macOS/Linux:
    python3 -m venv venv
    source venv/bin/activate

  Windows (PowerShell):
    python -m venv venv
    .\venv\Scripts\Activate.ps1

    Se receber erro de política de execução, rodar antes:
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

  Windows (CMD):
    python -m venv venv
    venv\Scripts\activate.bat


Passo 3 — Instalar dependências Python
  pip install -r requirements.txt

  ATENÇÃO — dlib no Windows:
    O dlib é compilado a partir do código fonte durante o pip install.
    Ele EXIGE o Visual Studio Build Tools 2022 com workload C++ instalado
    (ver Pré-requisitos). A compilação leva entre 5 e 15 minutos na
    primeira vez — isso é normal. Não interromper o processo.

    Se o pip install travar ou falhar com erro de compilação, verificar:
    1. Build Tools instalado com workload correto
    2. Reiniciar o terminal após instalar Build Tools
    3. Tentar novamente com: pip install dlib --verbose


Passo 4 — Configurar o .env

  Copiar o arquivo de exemplo:

    macOS/Linux:
      cp .env.example .env

    Windows (PowerShell ou CMD):
      copy .env.example .env

  Gerar JWT_SECRET_KEY:

    macOS/Linux:
      python3 -c "import secrets; print(secrets.token_hex(32))"

    Windows:
      python -c "import secrets; print(secrets.token_hex(32))"

  Gerar ADMIN_PASSWORD_HASH (senha padrão: watchman):

    macOS/Linux:
      python3 -c "from passlib.context import CryptContext; print(CryptContext(['bcrypt']).hash('watchman'))"

    Windows:
      python -c "from passlib.context import CryptContext; print(CryptContext(['bcrypt']).hash('watchman'))"

  Abrir o .env em qualquer editor e colar os valores gerados:
    JWT_SECRET_KEY=<valor gerado>
    ADMIN_PASSWORD_HASH=<valor gerado>

  Se ADMIN_PASSWORD_HASH ficar vazio, o backend aceita a senha "watchman"
  automaticamente como fallback de desenvolvimento.


Passo 5 — Instalar dependências do frontend
  cd frontend
  npm install
  cd ..

SOLUÇÃO DE PROBLEMAS COMUNS
================================================================

PROBLEMA: dlib falha na instalação (Windows)
CAUSA:    Build Tools não instalado ou versão/workload incorreto
SOLUÇÃO:  1. Baixar Visual Studio Build Tools 2022
             https://visualstudio.microsoft.com/visual-cpp-build-tools/
          2. Instalar com workload "Desktop development with C++"
          3. Reiniciar o terminal
          4. Reativar o venv e rodar: pip install -r requirements.txt

PROBLEMA: python-magic falha na importação (Windows)
CAUSA:    libmagic não existe nativamente no Windows
SOLUÇÃO:  pip uninstall python-magic
          pip install python-magic-bin

PROBLEMA: python-magic falha na importação (macOS)
CAUSA:    libmagic não instalado via Homebrew
SOLUÇÃO:  brew install libmagic
          (reinstalar o pacote não é necessário)

PROBLEMA: Erro "JWT_SECRET_KEY field required" ao subir o backend
CAUSA:    .env não foi criado ou está incompleto
SOLUÇÃO:  1. Verificar se o arquivo .env existe na raiz do projeto
          2. Se não existir: copy .env.example .env (Windows)
                             cp .env.example .env (macOS/Linux)
          3. Gerar e preencher JWT_SECRET_KEY conforme Passo 4
          4. Reiniciar o uvicorn

PROBLEMA: Frontend não consegue conectar ao backend (CORS / Network Error)
CAUSA:    Backend não está rodando ou está em porta diferente
SOLUÇÃO:  1. Verificar se o uvicorn está ativo no Terminal 1
          2. Confirmar que http://localhost:8002/api/v1/health responde
          3. CORS está configurado para portas 3000, 5173 e 5174 — não mudar
             a porta do npm run dev sem ajustar app/main.py

PROBLEMA: Status do vídeo trava em "Processando"
CAUSA:    Erro silencioso no worker de visão computacional
SOLUÇÃO:  Verificar os logs do terminal do backend — o worker registra
          exceções com traceback completo antes de marcar status "Erro"

PROBLEMA: Rostos não detectados no vídeo
CAUSA:    Vídeo com resolução muito baixa, faces de perfil ou threshold
          muito permissivo
SOLUÇÃO:  face_recognition funciona melhor com faces frontais e resolução
          mínima de 480p. Ajustar FACE_RECOGNITION_TOLERANCE no .env para
          valor menor (ex: 0.5) aumenta o rigor da correspondência.
          Valor padrão: 0.6 (quanto menor, mais estrito).

PROBLEMA: Erro de política de execução no PowerShell ao ativar venv
CAUSA:    Windows bloqueia scripts .ps1 por padrão
SOLUÇÃO:  Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
          Rodar apenas uma vez; persiste para a conta do usuário.

================================================================
DECISÕES TÉCNICAS RELEVANTES
================================================================

1. AppearanceWithVideo dataclass (v0.20)
   Schema interno que enriquece aparições com dados de vídeo no endpoint
   /people/{id}/timeline. Evita lazy-loading ORM cross-service ao montar
   a resposta sem retornar objetos SQLAlchemy fora da sessão.

2. StaticPool em fixtures de teste (v0.14)
   SQLite in-memory com StaticPool garante que o worker de processamento
   e a fixture de teste compartilhem a mesma conexão. Sem isso, o worker
   abre uma conexão separada e enxerga um banco vazio, causando falhas
   nos testes de integração.

3. setuptools<71 pin no requirements.txt (v0.11)
   O pacote face-recognition-models usa pkg_resources, que foi removido
   do setuptools>=71. Sem esse pin, Python 3.14+ quebra o import do
   face_recognition com ImportError.

4. FACE_RECOGNITION_TOLERANCE centralizado em settings.py (v0.03)
   O threshold de 0.6 (distância euclidiana) é configurável via .env.
   Valores menores (ex: 0.5) aumentam o rigor; valores maiores (ex: 0.7)
   tornam a correspondência mais permissiva. Nunca hardcodado no pipeline.

5. Embeddings salvos como .npy por person_id (v0.12)
   Vetores de face persistidos em storage/faces/{id}.npy permitem
   re-identificação entre sessões sem reprocessar vídeos anteriores.
   Pessoas sem .npy em disco são ignoradas com log de aviso.

6. asyncio.run_coroutine_threadsafe para bridge thread→asyncio (v1.25)
   O worker roda em ThreadPoolExecutor do FastAPI (thread síncrona).
   Para emitir eventos WebSocket (coroutines asyncio) a partir do worker,
   usa-se asyncio.run_coroutine_threadsafe(coro, loop) onde loop é o
   event loop principal armazenado em ws_manager._loop durante o lifespan.
   NUNCA usar asyncio.run() — levanta RuntimeError se o loop já estiver
   rodando.

7. Auth WebSocket via query param ?token=JWT (v1.25)
   A API WebSocket do JavaScript não suporta headers customizados
   (como Authorization: Bearer). A solução correta é passar o JWT
   como query param: ws://host/ws/video/1?token=<jwt>. O servidor
   chama verify_token(token) e fecha com code=1008 em caso de falha.

8. Exportação CSV via stdlib (v1.22)
   O endpoint GET /export/timeline usa csv.DictWriter + io.StringIO
   da stdlib, sem dependências externas. Retorna StreamingResponse com
   media_type="text/csv" e Content-Disposition: attachment.

9. Busca por similaridade carrega embeddings do disco a cada request (v1.32)
   search_by_face() chama get_all_embeddings() — recarrega todos os .npy
   do storage/faces a cada requisição. Custo deliberadamente exposto via
   query_time_ms no response. Com poucos perfis é imperceptível; evolução
   futura natural seria cache de embeddings em memória (ponto de discussão
   técnica em entrevista).

10. Alerta único por pessoa monitorada por vídeo (v1.31)
    alerted_in_this_video: set[int] no escopo de process_video evita
    duplicar alertas quando a mesma pessoa "Monitorado" aparece em
    múltiplos frames do mesmo vídeo.

11. Modelo de detecção facial CNN (v1.5.5)
    O modelo padrão do face_recognition (HOG) falha em faces
    pequenas, de perfil ou com iluminação adversa. Trocado para
    CNN (model="cnn") que usa rede neural convolucional com
    aceleração Apple Silicon no M4. Configurável via
    FACE_DETECTION_MODEL no .env. FACE_UPSAMPLE=2 para câmeras
    distantes (dobra o tempo de processamento por frame).
    Tradeoff documentado: CNN é ~3-5x mais lento que HOG por frame,
    compensado pela redução de amostragem se necessário.

PARA VÍDEOS DE CÂMERA DE SEGURANÇA (arquivos 5GB+)
================================================================

Configurações no .env para câmeras CFTV/Catraca:
  MAX_UPLOAD_SIZE_MB=5120            # 5GB
  FACE_DETECTION_MODEL=cnn           # maior precisão
  FACE_UPSAMPLE=1                    # ou 2 se câmera distante
  FRAMES_PER_SECOND_SAMPLE=2         # 2 frames/s vs 1 padrão

Iniciar backend com timeout estendido:
  source venv/bin/activate
  uvicorn app.main:app --reload --port 8002 --timeout-keep-alive 300

Formatos suportados:
  MP4, AVI, MKV, MOV, TS
  Magic bytes validados antes do upload

Dica para vídeos muito longos (>30 min):
  Extrair trechos de 15-20min e processar separadamente.
  Dobro de frames/s (2/s vs 1/s) = ~2h processamento por 1h vídeo com CNN.
  Se o vídeo for outro formato (MPEG-TS, H264 raw):
    ffmpeg -i entrada.ts -c copy -bsf:v h264_mp4toannexb saida.mp4
  Ou usar ffmpeg para converter para MP4 antes do upload.

Tratamento de erro em vídeos grandes:
  Se status = Erro e há "MemoryError" nos logs:
    - Arquivo pode estar corrompido ou muito grande
    - Tente um trecho menor (5-10 min) para calibrar
    - Aumentar RAM disponível se der timeout

Progresso do processamento:
  Backend loga a cada 100 frames: Processados X frames | Y faces | Z novas pessoas
  WebSocket notifica o frontend em tempo real via /ws/video/{id}

SPRINT 16 — PRECISÃO DE RECONHECIMENTO FACIAL (v1.9.1–v1.9.4)
================================================================

Três melhorias cirúrgicas no pipeline para reduzir falsos positivos:

1. Filtro de qualidade de frame (is_good_quality_frame):
   - Descarta rostos < FACE_MIN_SIZE_PX (60px) ou borrados
     (variância Laplaciana < FACE_BLUR_THRESHOLD = 100.0)
   - extract_embeddings agora retorna list[(embedding, location)]

2. Agregação por aparição contínua (FaceTrack/FaceTracker):
   - Agrupa detecções consecutivas (gap ≤ FACE_TRACK_GAP_TOLERANCE = 2.0s)
   - Descarta tracks com < FACE_TRACK_MIN_SAMPLES (2) amostras
   - Identidade resolvida 1x por track usando mean_embedding() —
     muito mais estável que embedding de frame isolado
   - get_best_crop() salva o recorte do frame com maior área de rosto

3. Votação k-NN (find_matching_person):
   - Em vez de aceitar cegamente o vizinho mais próximo (argmin),
     pega os FACE_KNN_K (3) vizinhos dentro da tolerância e vota
     por maioria de person_id — reduz viés de pessoas
     super-representadas no banco de embeddings

FACE_TRACK_GAP_TOLERANCE, FACE_TRACK_MIN_SAMPLES, FACE_KNN_K
